Demonstration panel isolated demo queue & workers -- never touches normal traffic

1. Send twice

Submits the same ticket twice with the same idempotency key. Both requests should return the identical job.

2. Fail this attempt

Submits a demo ticket that fails its first attempt on purpose, then retries and succeeds.

3. Stop this worker

Kills the real demo worker process handling a slow ticket, mid-job. A sibling worker recovers it once the queue notices.

These controls only ever affect isolated demo tickets and the demo worker pool this server spawned for itself -- they cannot touch a normal visitor's upload or any other process. This app is a local demonstration and is not deployed publicly.
